Module 01

Cloud Concepts Overview

Fewer marks

Section 1What cloud computing actually is

Definition to memorise: Cloud computing is the on-demand delivery of compute power, database, storage, applications and other IT resources over the internet, with pay-as-you-go pricing.

Break that sentence into three ideas, because markers usually look for all three:

  • On-demand — you get it when you ask for it, in minutes, not weeks.
  • Over the internet — you don't own or touch the machine.
  • Pay-as-you-go — you pay for what you use, and you stop paying when you stop using.

The big mental shift in this module is: stop thinking of infrastructure as hardware, start thinking of it as software. Instead of buying a server, you write a line of code or click a button and a server appears.

Example

A student club wants a website for a 3-day event. The old way: buy a server (RM4,000), wait 3 weeks for delivery, set it up, and keep it in a room forever after the event. The cloud way: launch an EC2 instance in 2 minutes, pay a few ringgit for 3 days, then terminate it and pay nothing more.

Example

Uploading 100 GB of photos into S3 costs nothing for the transfer in. Storing them costs per GB per month. Your users downloading those photos to the internet is the part that gets billed as outbound transfer.

The four ways AWS pricing saves you money

  • Pay for what you use — pay only for the services you consume, with no large upfront expense. Start and stop anytime, no long-term contract.
  • Pay less when you reserve — commit to a 1-year or 3-year term with Reserved Instances and save up to 75 percent.
  • Pay less by using more — volume-based discounts. The more storage you use in services like S3, EBS and EFS, the less you pay per GB.
  • Pay even less as AWS grows — AWS keeps lowering its own cost of doing business and passes the savings on. It had already lowered pricing 75 times as of September 2019, and higher-performing hardware replaces older hardware at no extra charge.

Section 3AWS Organizations

AWS Organizations lets you consolidate multiple AWS accounts so you can manage them centrally. The terminology to know is root (the top container), organizational units (OUs) (groups of accounts), and accounts themselves.

Key features and benefits

  • Policy-based account management — attach policies to control what accounts can do.
  • Group-based account management — organise accounts into OUs and manage them as a group.
  • APIs that automate account management — create and manage accounts programmatically.
  • Consolidated billing — one bill for all accounts, and combined usage can reach volume discounts faster.

Options include virtual MFA apps (Google Authenticator, Authy), U2F security keys (such as YubiKey), and hardware MFA such as a key fob or display card from Gemalto.

Authorization: what you are allowed to do

Three rules decide every request, and they run in a fixed order:

  1. Is it explicitly denied? If yes → Deny. An explicit deny always wins and can never be overridden.
  2. Is it explicitly allowed? If yes → Allow.
  3. Neither? → Deny by implicit deny. All permissions are denied by default.

The guiding rule is the principle of least privilege: give an identity only the permissions it actually needs, nothing more.

The four steps to secure a new account

  1. Stop using the account root user as soon as possible. While logged in as root: create an IAM user for yourself; create an IAM group with full administrator permissions and add your user to it; disable and remove the root access keys if they exist; enable a password policy for users; sign in with the new IAM credentials; store the root credentials somewhere safe.
  2. Enable multi-factor authentication (MFA) for the root user and for all IAM users. MFA can also control access to AWS service APIs.
  3. Use AWS CloudTrail. It tracks user activity and logs all API requests to resources in supported services. Basic event history is on by default, is free, and covers the latest 90 days of management events. To keep logs beyond 90 days or enable alerting, create a trail, apply it to all Regions, and store logs in an S3 bucket with restricted access.
  4. Enable a billing report such as the AWS Cost and Usage Report. It records usage and estimated charges by hour or by day and is delivered to an S3 bucket you specify, updated at least once per day.
Exam tip — write all seven best practices

If asked "state the best practices to secure an AWS account", give all seven with a short reason each: secure logins with MFA · delete root access keys · create individual IAM users and apply least privilege · use groups to assign permissions · configure a strong password policy · delegate using roles instead of sharing credentials · monitor account activity with CloudTrail.

CIDR notation — read it slowly once and it stays

CIDR stands for Classless Inter-Domain Routing. An address is written as 192.0.2.0/24. The number after the slash tells you how many bits are fixed.

  • The fixed part is the network identifier (also called the routing prefix). It does not change.

An IPv4 address has 32 bits in total. So the number of usable addresses is 2 raised to the power of (32 − prefix).

Route tables

A route table contains a set of rules (routes) that direct network traffic from a subnet. Each route specifies a destination and a target.

What "stateful" means in plain words

Stateful (security group): if you allow a request in, the reply is automatically allowed back out. You only write one rule.

Exam tip

Note the default vs custom trap for network ACLs: the default ACL allows everything, but a custom ACL you create denies everything until you add rules. Examiners love this reversal.

  • Choose the appropriate gateway device or VPN connection for your needs.
  • Use firewalls — security groups and network ACLs are the two firewall options inside a VPC.

Section 5Amazon Route 53

Amazon Route 53 is a highly available and scalable Domain Name System (DNS) web service. Section 2Amazon EC2

Amazon EC2 provides virtual machines — called instances — in the cloud. You get full control over the guest operating system (Windows or Linux). You can launch instances of any size into an Availability Zone anywhere in the world, launch them from Amazon Machine Images (AMIs), have them ready in minutes, and control the traffic to and from them.

Typical uses: application server, web server, database server, game server, mail server, media server, catalog server, file server, computing server, proxy server.

The nine decisions when launching an instance

This is a real sequence, so the order matters. It is also a strong candidate for a "list and explain the steps" question.

  1. Select an AMI. An Amazon Machine Image is a template used to create an EC2 instance. It contains a Windows or Linux operating system and often some pre-installed software. Sources: Quick Start (provided by AWS), My AMIs (ones you created), AWS Marketplace (pre-configured third-party templates), and Community AMIs (shared by others — use at your own risk).
  2. Select an instance type. This determines memory (RAM), processing power (CPU), disk space and disk type, and network performance.
  3. Specify network settings. Which VPC and optionally which subnet, and whether a public IP address is auto-assigned so the instance is reachable from the internet.
  4. Attach an IAM role (optional). Needed if software on the instance must call other AWS services. The role is held in an instance profile. You can also attach a role to an instance that already exists.
  5. Add a user data script (optional). A script that runs the first time the instance starts, used to customise the runtime environment. It reduces how many custom AMIs you need to build and maintain.
  6. Specify storage. Configure the root volume where the guest OS is installed, and optionally attach more volumes. For each volume set the size in GB, the volume type, whether it is deleted on instance termination, and whether it is encrypted.
  7. Add tags. A tag is a label made of a key and an optional value. Tags attach metadata to the instance and help with filtering, automation, cost allocation and access control.
  8. Configure the security group. A set of firewall rules controlling traffic to the instance. It exists outside the instance's guest OS. Each rule specifies the port number, the protocol (TCP, UDP or ICMP), and the source allowed to use the rule.
  9. Identify or create the key pair. A public key stored by AWS and a private key file stored by you. On Linux you use the private key to connect over SSH; on Windows you use it to obtain the administrator password.
Watch out

AWS does not keep a copy of your private key. If you lose the .pem file, you lose access to that instance. This is a favourite short-answer question.

Section 2Amazon Simple Storage Service (Amazon S3)

In S3, data is stored as objects inside buckets. Key facts:

  • Virtually unlimited total storage.
  • A single object is limited to 5 TB.
  • Designed for 11 nines (99.999999999%) of durability.
  • Granular access control at both bucket and object level.
  • Data is redundantly stored across facilities within the Region.

To use it: create a bucket in an AWS Region, then upload almost any number of objects to it. You can reach the data through the Management Console, the CLI, or an SDK.

Section 3Amazon Elastic File System (Amazon EFS)

Amazon EFS provides file storage over a network — many EC2 instances can mount the same file system at the same time and share files.

How to implement it, in order:

  1. Create your Amazon EC2 resources and launch your instance.
  2. Create your Amazon EFS file system.
  3. Create your mount targets in the appropriate subnets.
  4. Connect your EC2 instances to the mount targets.
  5. Verify the resources and protection of your AWS account.

An EFS mount target has a subnet ID and security groups. You create one per Availability Zone, inside a VPC subnet, and all mount targets must be in the same VPC. File systems also carry tags as key-value pairs.

Section 3Amazon Redshift

Amazon Redshift is a fast, fully managed data warehouse service. It uses a parallel processing architecture: SQL clients and business intelligence tools connect to a leader node, which distributes work across dense compute nodes (each with virtual cores, RAM and local disk). It can also work with data in Amazon S3 and DynamoDB.

Why columnar storage matters

A normal database stores a whole row together. A data warehouse question is usually "what was the total sales for 2025?" — it needs one column across millions of rows. Columnar storage keeps each column together, so Redshift reads only what it needs and answers far faster.

Section 4Amazon Aurora

Amazon Aurora is an enterprise-class relational database that is compatible with MySQL or PostgreSQL. It automates time-consuming tasks such as provisioning, patching, backup, recovery, failure detection and repair.

Features: high performance and scalability · high availability and durability with a resilient design · multiple levels of security · compatible with MySQL and PostgreSQL · fully managed.

Ten answers to have word-perfect

  1. Cloud computing — the on-demand delivery of compute power, database, storage, applications and other IT resources via the internet with pay-as-you-go pricing.
  2. The shared responsibility model — AWS is responsible for security of the cloud; the customer is responsible for security in the cloud.
  3. The six advantages of cloud computing — trade capex for variable expense; massive economies of scale; stop guessing capacity; increase speed and agility; stop spending on running data centres; go global in minutes.
  4. Region vs Availability Zone vs edge location — a Region is a geographical area holding two or more AZs; an AZ is a fully isolated partition made of discrete data centres; an edge location caches content close to users for CloudFront.
  5. Security group vs network ACL — instance level vs subnet level; allow only vs allow and deny; stateful vs stateless; all rules evaluated vs evaluated in number order.
  6. IAM permission evaluation — explicit deny wins; otherwise explicit allow permits; otherwise implicit deny blocks.
  7. The four EC2 cost optimisation pillars — right size, increase elasticity, optimal pricing model, optimise storage choices.
  8. Block vs object storage — to change one character, block storage updates only that block, object storage rewrites the entire file.
  9. Multi-AZ vs read replica — Multi-AZ is synchronous and exists for availability; a read replica is asynchronous and exists for read performance.
  10. Relational vs non-relational — rows and columns with a fixed schema and vertical scaling, versus key-value/document/graph with a dynamic schema and horizontal scaling.
